# ADR-0099: Consistency pass and generated types index

Status: accepted · Origin: review round 25 (2026-09-29)

## Decision

`docs/design/types.md` is generated by `tools/gen_types_index.py` from the capability specs and is the checklist for M0 task 1; a duplicate definition across specs fails generation review. Fixes applied: shared-state accessors renamed `SharedState`/`SetSharedState` (clash with the stepper `State` type); `Caps.Context` dropped in favour of the existing `ModelProfile.ContextWindow`; `Compaction` defined once in `messages`; `InputRequest` and the token sentinel errors moved to `suspension`; previously undefined identifiers defined in their owning specs (`GuardInput`, `StepKind`, `ExprBudget`, `AbortError`, `ErrNoPrincipal`, `Usage.ModelVersion`, `ErrRunActive`, `ErrOperationExists`, `ErrCheckpointIncompatible`, `ErrManifestDrift`, `ErrToolSetDrift`); taint matching gets a per-turn rolling-hash index, a window cap and a performance budget; frontend tools' `Exfil` default stated in `agui` and `taint`; repository layout lists the new `std` packages and adapters; overview counts corrected.

## Context and evidence

A reference index over the 35 specs found two compile-level clashes, one duplicated field, one duplicated type and eleven referenced-but-undefined identifiers, most pre-dating today's rounds. Indexing is cheap and catches this class before implementation.

## Consequences

`tools/gen_types_index.py` runs in CI (`task spec:types`) alongside `spec:coverage`; a spec change that introduces a duplicate or an undefined identifier fails the check.
