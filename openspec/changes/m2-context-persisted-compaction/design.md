# Design: m2-context-persisted-compaction

## Context

See `proposal.md` — Why. The behaviour is already normative in `openspec/specs/context/spec.md` (*Contract*, "Two stages with different persistence", rules 1, 3, 5, 6; requirement *Compaction is persisted*). This design decides the seams that connect it to the live tree. Read against the tree on 2026-10-07:

- **The `Compactor` seam is declared but unreachable.** `stores.Compactor` exists (`core/stores/projection.go:20-26`) and `ContextPolicy.Compactor` is carried (`core/stores/projection.go:28-33`), but `Compactor` is referenced nowhere outside its declaration: the assembly composition reads only `policy.Projections` (`core/native_effects.go:277-299`), and the policy binds through `WithContextPolicy` (`core/build_options.go:205-213`). The shipped `Compact` returns `History`; the capability Contract returns `Compaction` (`openspec/specs/context/spec.md`, *Contract*).
- **The block and the event already exist.** `types.Compaction{BlockBase, CoversUpTo int64, Kind, Summary []Block, Opaque Raw, Model string, Tokens int}` (`core/types/message.go:156-172`) and `types.Compacted{FromVersion, ToVersion int64, TokensBefore, TokensAfter int, Policy string}` (`core/types/event.go:92-99`). `Compaction` is a registered block kind (`core/types/message.go:225`, `:255-256`, codec at `:408-442`), and `Compacted` is a registered event (`core/stores/events.go:322`). Both marshal through the record envelope.
- **The version mapping is exact.** `History.Version` is the count of appended messages: `Append` does `rec.hist.Version += int64(len(msgs))` (`core/stores/session_memory.go:381`) and `Load` returns `Messages` in append order (`core/stores/session_memory.go:308-330`). A `Compaction` block's `CoversUpTo` therefore names a message count: the first `CoversUpTo` messages are the ones it replaces.
- **The assembly seam.** The native path composes `withProjections(cfg.contextPolicy, cfg.profile, nativeAssemble(...))` (`core/native_effects.go:31`; foreign flows mirror it at `core/foreign_conversation.go:77`). `withProjections` clones the loaded messages and runs the declared projections (`core/native_effects.go:273-299`); `nativeAssemble` is the caller assembler plus blobs, redaction and the operator-turn fence (`core/native_effects.go:227-262`).
- **The drive seam.** The turn loop runs in `driveTurns` (`core/drive_turn.go:152`) and the model invocation in `modelEffect` (`core/drive_turn.go:252-271`), which assembles through `c.assemble`. Persisting a block goes through `HistoryAppender` (`core/drive_lifecycle.go:95`), read from ctx by `historyAppenderFrom` (`core/drive_turn.go:585-588`).
- **The decision ports ship.** `ContextBudget(p, req, est, ratio)` and `NeedsCompaction(ctx, p, req, m)` (`core/types/context_budget.go:16-58`); `Truncate` carries `WithTruncateEstimator`/`WithTruncateRatio` (`std/context/truncate.go:20-42`).
- **The guard seam ships.** `guards.GuardInput{Stage, Blocks, Origin, Run}` (`core/guards/guard.go:33-44`), `ConsultGuard` opens the `gohan.guard` span and runs the guard (`core/telemetry.go:75`), and `std/guard.ContextGuard.Decide` rejects instruction-like content for tool/provider/model/operator origins (`std/guard/context.go:33-71`).
- **Counters are a shipped port.** `types.Telemetry.Count(ctx, name, n, attrs...)` (`core/types/telemetry.go:9-20`); `gohan.guard.context_rejected` and `gohan.context.compactions` are named in the telemetry spec (`openspec/specs/telemetry/spec.md:96,102`), and the telemetry spec's second column states the attribution (`provider`/`kind`).
- **The invariant guard file already exists.** `core/projection_invariants_test.go` asserts pending-call survival, tool-use/result adjacency, the taint-over-full-log window and journal fingerprints; this change must keep it green.

## Goals / Non-Goals

**Goals:** reconcile the `Compactor` seam to the Contract, collapse the loaded log by the persisted `Compaction` blocks during assembly, ship a harness-side `Summarize` whose summary is guarded before persistence, run the compaction stage in the drive with the `CoversUpTo` clamp, persist the block, and write the `Compacted` audit record and event — turning the five owned ids green on the public path.

**Non-Goals:** This change ships no `ProviderCompact`, no `Caps.Compaction` handling and no `Build` fallback rejection — those are `m2-provider-compaction` (`context.opaque-bound-to-model`, `context.opaque-fallback-rejected`). It ships no calibration ratio, no `State.Calibration` and no overflow retry — those are `m2-context-calibration-overflow`. It does not add `PromptSet.Compaction`, tuning or a policy-source type: the `Summarize` policy surface is M4 (`openspec/changes/m2/design.md` §3 item 2). It does not change `Truncate`, `ClearToolResults`, the taint window or the journal.

## Decisions

### D1 — The persistence stage runs in the drive, not in the projection wrapper

`withProjections` runs inside assembly and its seam deliberately carries no store handle (`core/stores/projection.go:12-19`). A persisted compaction appends to `SessionLog`, so it runs where the run holds an appender and the run state: the drive turn (`core/drive_turn.go:152`, hooking the model invocation at `core/drive_turn.go:252-271`). The stage reads `policy.Compactor` (nil disables it), decides with `types.ContextBudget`/`types.NeedsCompaction` (`core/types/context_budget.go:16-58`) or a declared token trigger, and appends through the `HistoryAppender` the harness installs (`core/drive_lifecycle.go:95`).

### D2 — Covered versions are hidden by an intrinsic assembly step, not a declared projection

Hiding is not opt-in: it is how a persisted `Compaction` block is rendered. The change adds a collapse step in the same composition as `withProjections` (`core/native_effects.go:31`, `core/foreign_conversation.go:77`), running before the declared projections and independent of `ContextPolicy.Projections`. It scans the loaded messages for the newest `types.Compaction` block, drops the first `CoversUpTo` messages, and puts that block at the head of the view. Rationale: the block is already in history, so hiding needs no store handle and replay reads it straight off the log — a replayed run assembles exactly what the original did (`context.replay-after-compaction`). A log with no `Compaction` block returns the messages unchanged.

### D3 — `Compactor.Compact` returns the block, and the stage clamps `CoversUpTo` below pending calls

The Contract's signature is `Compact(ctx, h History, p ModelProfile) (Compaction, error)` (`openspec/specs/context/spec.md`, *Contract*); the shipped stub returns `History` and is reconciled to the Contract — an additive change to the declaration in `core/stores/projection.go`, with `ContextPolicy.Compactor` unchanged so no frozen struct gains a field. The compactor computes a candidate `CoversUpTo` from the history version; the drive stage clamps it below the earliest `ToolUse` whose `ToolResult` is absent from history (`Outcome: Unknown`, pending or approval-suspended), using the same history-order scan `scanUses` performs in `std/context/clear_tool_results.go`. The clamp is a write-side rule (`context.pending-call-survives`), so it lives where the block is persisted, not in the projection view.

### D4 — `std/context.Summarize` produces `CompactionText` from a declared `SummarySource`

`Summarize` is a `stores.Compactor` in `std/context`, beside `Truncate` and `ClearToolResults`. It folds the covered messages into a `types.Compaction{Kind: CompactionText, CoversUpTo, Summary: ...}` whose `Summary` blocks come from a declared `SummarySource` value on the `Summarize` (`func(ctx, stores.History, types.ModelProfile) ([]types.Block, error)`), carrying `Origin{Kind: OriginModel}`. A nil source is inert and returns an error rather than persisting an empty summary. The `PromptSet.Compaction` instruction, tuning and the policy-source type are M4 (`openspec/changes/m2/design.md` §3 item 2); M2 ships the mechanics and the guard, not the policy. Alternative rejected: importing the M4 prompt field now, which would pull M4's policy surface into M2's freeze.

### D5 — The summary is guarded at `StageContext` before the append, and a rejection falls back to `Truncate`

The stage runs the produced `Summary` blocks through `ConsultGuard` at `StageContext` with the blocks' own origin (`core/telemetry.go:75`, `core/guards/guard.go:33-44`, `std/guard/context.go:51-71`). A blocked decision persists nothing: the stage leaves the log untouched, applies the flow's `Truncate` projection for the turn, emits a `types.GuardBlocked` event, and counts `gohan.guard.context_rejected` with the `provider="compaction"` attribute (`types.Telemetry.Count`, `core/types/telemetry.go:9-20`). This is the guarded behaviour `context.summary-guarded` names; the audit and ledger stay clean because no block was written.

### D6 — The audit record is an additive payload, and the Contract edit is declared

The `Compacted` audit record is written with a new `AuditCompacted AuditKind = "compaction"` and the facts the requirement names — from/to version, tokens before/after, policy name, summary checksum — carried on an additive `AuditRecord` payload: `Compaction *CompactionAudit{FromVersion, ToVersion int64; TokensBefore, TokensAfter int; Policy, SummarySHA string}`. Both the `AuditKind` const block and the `AuditRecord` struct are Contract code in `openspec/specs/stores/spec.md:284-311`; those edits, and the regenerated `docs/design/types.md` rows, land with the main-spec edit at apply time. ADR-0090 decides the `Compaction`/`Compacted` shapes (context management), and ADR-0157 decides the envelope: an additive record change needs no upcaster (`openspec/specs/stores/spec.md:338`). The `Compacted` event (`core/types/event.go:92-99`) and the `gohan.context.compactions` counter (`gohan.context.tokens_before`/`tokens_after` recorded from the block's `Tokens`) are written in the same stage.

## Risks / Trade-offs

- [Risk] The collapse step drops a message a projection still needs, or the wrong ones under a clamped `CoversUpTo`. → Mitigation: hiding uses only `CoversUpTo` against the store's `Version == len(Messages)` invariant (`core/stores/session_memory.go:381`), the clamp runs before the append so the persisted value is already safe, and the view step is asserted against `core/projection_invariants_test.go` (pending-call survival, adjacency) which must stay green.
- [Risk] Guarding after the append would persist a rejected summary. → Mitigation: D5 orders guard → append, and `context.summary-guarded` asserts nothing is persisted and `Truncate` takes the turn.
- [Risk] Extending `AuditRecord` touches a `stores` Contract block. → Mitigation: the payload is additive and the edit is declared in D6; the envelope carries the record's `SchemaVersion` regardless, and no upcaster is required.
- [Risk] A `Summarize` without the M4 prompt produces a summary the model never sees the intent of. → Accepted and stated: M2 ships the guarded, persisted mechanics; the policy surface is M4, and a nil `SummarySource` is inert rather than silently persisting.

## Migration Plan

No data migration. The change reconciles the `Compactor` signature, adds one assembly view step, one `std/context` compactor, one drive stage, and the `AuditCompacted` payload. A flow with no `Compactor` and a log with no `Compaction` block behaves exactly as today. `docs/design/types.md` is regenerated for the changed declarations; no version is cut by this change. Shared driver files (`core/native_effects.go`, `core/drive_turn.go`) follow the milestone's admission-order rule (`openspec/changes/m2/tasks.md:19`): the `m2-sandbox-lifecycle-resume` lane is admitted after this one, and the two lanes never touch a shared driver file concurrently.
