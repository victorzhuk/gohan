# Proposal: m2-context-persisted-compaction

## Why

The `context` capability splits history shaping into two stages with different persistence, and only the first has code. `stores.Compactor` is declared (`core/stores/projection.go:24-26`) but nothing calls it; `ContextPolicy.Compactor` is carried but never resolved (`core/build_options.go:208-215`); no `Summarize` exists in `std/context`; and the assembly wrapper composes projections directly into the caller assembler (`core/native_effects.go:31`) without ever collapsing a persisted `Compaction` block. Five registered scenario ids therefore have no public-path behaviour: `context.compaction-persisted`, `context.replay-after-compaction`, `context.pending-call-survives`, `context.summary-guarded`, `context.compaction-audited` (`openspec/changes/m2/design.md:53-73`, all `deferred_to: M2`).

Without this change a long session overflows and re-summarizes every turn: the compaction is never written to `SessionLog`, so `Replay` diverges and the audit trail has no `Compacted` record. The projection stage that must run underneath it already ships (`m2-context-projections`, archived 2026-10-07); persisted compaction is the seam it was built for (`openspec/specs/context/spec.md`, *Contract*, "Two stages with different persistence", rule 7).

## What Changes

- **Breaking:** migrate the exported `stores.Compactor` declaration from `Compact(ctx context.Context, h History, p types.ModelProfile) (History, error)` to the capability Contract's `Compact(ctx context.Context, h History, p types.ModelProfile) (Compaction, error)` (`core/stores/projection.go:24-26`; `openspec/specs/context/spec.md`, *Contract*, which already declares the target return type). The interface changes its result type, so the declaration, every implementation and every caller migrate in one change with no compatibility alias (task 1.4). The `ContextPolicy.Compactor` field is unchanged, so no frozen struct gains a field.
- Add the compaction view to the native assembly path: before the declared projections, collapse the loaded history by the newest `types.Compaction` block, removing it from its original position, dropping the messages it covers and dropping every superseded `Compaction` block, then rendering exactly one summary at the head of the view. The collapse runs even when no projection is declared. The store keeps `History.Version == len(History.Messages)` (`core/stores/session_memory.go:331-385`), so the mapping is exact and replay reads it straight off the log.
- Add `std/context.Summarize`: a `stores.Compactor` that folds the covered messages into a `CompactionText` block whose `Summary` comes from a declared `SummarySource`. The `PromptSet.Compaction` instruction, tuning and policy source stay with M4 (`openspec/changes/m2/design.md` §3 item 2).
- Add the compaction stage to the native drive and to the foreign runtime path: select a turn-aligned safe prefix before the summary source (whole `ToolUse`/`ToolResult` pairs, no pending call), decide the trigger by overflow after projections via the profile's `TokenCounter` or the declared `WithEstimator` (`core/types/context_budget.go:16-58`, `core/build_options.go:197-203`), run the compactor over the prefix, refuse a returned `CoversUpTo` that differs from it, guard the summary through `ConsultGuard` at `StageContext` (`core/telemetry.go:75`, `std/guard/context.go`), and on rejection persist nothing, apply the caller-injected fallback once and refuse the provider call when the request still exceeds its budget, while counting `gohan.guard.context_rejected{provider="compaction"}`. Core cannot construct a fallback from `std/context`, so `Build` takes it through `WithCompactionFallback` and refuses an active `Compactor` with no resolvable counter or no validated fallback.
- Persist: append the guarded `Compaction` block to `SessionLog` through the run's `HistoryAppender` (`core/drive_turn.go:581-590`), write the `Compacted` audit record (`core/stores/audit.go`) and emit the `types.Compacted` event (`core/types/event.go:92-99`).
- Persist the publication facts with the block and reconcile every publication: the publication payload (including the publishing run) is stored in the message metadata in the same append, its identity is a deterministic hash of session, publishing run and loaded version that the driver knows before the append, and the store assigns it to the stored message. Three optional store interfaces make each write atomic and identity-keyed, so reconciliation never reads a sink to prove absence. Before every actual provider invocation the harness inspects every durable publication, not only the newest block, and completes each missing sink under the original publishing run; this reconciliation is unconditional, so it also covers an invocation with no active `Compactor` and a foreign runtime that calls `Model.Generate` directly. The audit payload is additive and covered by a deterministic hash segment shared by the memory and Postgres logs, so a record sealed before the payload existed still verifies.
- Public-path coverage in `core` over `Build`, `Send` and `Resume` for both a native flow and a foreign flow whose runtime calls the model directly, and unit coverage in `std/context` and `core/stores`, with each owned id bound to a named subtest.
- **Runtime compatibility is preserved:** a flow with no `Compactor` and no `Compaction` block in its log assembles exactly as today, and the view step is a no-op when the log carries no compaction. Only the exported `Compactor` declaration's result type changes, and it changes with its implementations in the same change.

## Capabilities

### New Capabilities

None.

### Modified Capabilities

- `context`: Complete the *Compaction is persisted* requirement with the append-and-hide mechanics, the `CoversUpTo` clamp, replay equality, the guarded-summary fallback with its counter, and the `Compacted` audit record and event, and add focused requirements for the admission findings: safe prefix chosen before the summary, whole-pair coverage decided by matching ids, one rendered current summary at the view head, a durable publication payload with a predetermined identity, reconciliation of every publication at every native and foreign provider invocation boundary, atomic identity-keyed sink appends, audit-hash payload coverage with backward verification, counting and a validated injected fallback required at `Build`, one trigger, and the same-turn measurement of the request actually sent (`openspec/specs/context/spec.md`). The new scenario ids are proposed, not yet registered. Opaque model binding is not part of this change: those two scenario blocks are reproduced only because the MODIFIED block must stay complete.

## Impact

The package touches `core/stores` (the `Compactor` signature beside `History`, the `AuditCompacted` kind, the additive `AuditRecord.Compaction` payload, and the shared audit-hash segment), `std/context` (`Summarize` beside `Truncate` and `ClearToolResults`), `core/native_effects.go` (the collapse step in the assembly composition), `core/drive_turn.go` (the compaction stage with the safe-prefix selection and publication reconciliation), `core/build_options.go`/`core/build.go` (`WithCompactionFallback` and the active-compaction counting/fallback refusal), `core/foreign_conversation.go`/`core/stream_lifetime.go`/`core/resume.go`/`core/recover.go` (the collapse step on the foreign path, parent-context and `sessionID` propagation through `foreignAgentRun` and the `foreignRun` closure, and the pre-execution bindings of the session load, `SessionCompactionAppender`, configured sinks and durable run identity), `adapter/postgres` (one additive goose migration `00006_compaction_publication.sql` adding the nullable `publication_id` identity columns and their two partial unique indexes, `adapter/postgres/audit.go` and `adapter/postgres/events.go` for the shared hash segment, the atomic compaction appends, and `adapter/postgres` sessions for `AppendCompaction`) and `docs/design/types.md` (the regenerated index). The Contract edits, the ADR documentation entry and the `openspec/scenarios.json` registration of the proposed ids land at apply time. It adds three compaction-specific optional store interfaces, no method on an existing port, and no new capability. Provider compaction, calibration, the overflow retry and the `Summarize` policy surface stay out of scope with `m2-provider-compaction` and `m2-context-calibration-overflow` (`openspec/changes/m2/design.md:53-73`).
