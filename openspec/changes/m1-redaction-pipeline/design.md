# Design: m1-redaction-pipeline

## Context and scope

This package owns `redaction.pseudonym-stable-within-session`, `redaction.stores-never-see-raw-entities`, `redaction.streaming-rehydration`, `redaction.hallucinated-token-dropped`, `redaction.residency-enforced-at-build`, and `guards.redaction`. The milestone matrix records these as missing (`openspec/changes/m1/design.md:115-124`). `EraseSubject`, erasure records, deletion, and the four erasure scenario IDs remain owned by `m1-subject-erasure-residency`.

ADR-0157 is authoritative for the core ports, registration and persistence seams. Its decisions 1–3 replace the former unresolved D2 and D6 contracts. The accepted ADR assigns shared specification amendments and `docs/design/types.md` regeneration to the driver; this package does not edit those files. Root compatibility remains pre-v1 through M2.

Existing live paths establish integration points, not completed redaction behavior. `core/NativeSpec` and `resolveNative` currently resolve `Decider` and `TaintPolicy` (`core/native_options.go:16-35`, `core/native_resolve.go:104-121`). `core/stores.Stores` currently has four fields and no `RedactionMaps` (`core/stores/stores.go:6-11`). Implement ADR-0157's approved ports and options; do not describe future functionality as already shipped.

## Normative API and construction

`core/types` declares `Redactor`, `RedactionPolicy`, `TokenMode`, `EntityKind`, `Entity`, `Span`, `Detector`, and `RedactionMap` in `core/types/redaction.go`. `Redactor` has exact methods:

```go
Redact(ctx context.Context, blocks []Block, p RedactionPolicy) ([]Block, RedactionMap, error)
Rehydrate(ctx context.Context, blocks []Block, m RedactionMap) ([]Block, error)
```

The package implementation is `std/redact`, which implements `types.Redactor`. Flow registration uses the build-contract option `WithRedactor(types.Redactor) Option`. Its option stores the value in native configuration, and Build resolution transfers it to each resolved flow using the same path as `Decider` and `TaintPolicy`: option application in `Build` (`core/build.go:111-151`), native registration (`WithNativeAgent`, `core/native_options.go:37-45`), and resolution (`(*Stack).resolveNative`, `core/native_resolve.go:41-124`). Do not add `NativeSpec.Redactor`, an `any` field, a separate builder, or a second policy-registration path. The redactor and policy must be available on Send and Resume through the resolved native configuration and run identity, not reconstructed from projected history.

`types.RedactionMap` contains tenant, session, and token-to-entity entries. The port is `stores.RedactionMaps` with exact signatures `Put(ctx context.Context, tenant, session string, m RedactionMap) error` and `Get(ctx context.Context, tenant, session string) (RedactionMap, error)`. Add it to `stores.Stores`; key reads and writes by tenant and session. Retain maps independently from checkpoints and journal entries. A checkpoint never carries the map, map reference, or map payload. Resume loads the map from `Stores.RedactionMaps` before output can be released. Map-retention policy remains independent; subject erasure consumes this store under the separately owned `EraseSubject` contract.

Residency uses `RegionProvider` beside store ports, with exact method `Region() string`. At Build, for a tenant with `Residency` set, check every configured store implements `RegionProvider` and returns a non-empty value, and check every reachable profile's `Region` matches. A missing interface or empty region fails closed. Return an error naming tenant, store or profile, required region, and actual region. Do not invent a default region or treat absent evidence as compliance. `Tenant.Residency` is already present (`core/types/identity.go:73`) and `ModelProfile.Region` is already present (`core/types/model_profile.go:15`). `EraseSubject` stays with `m1-subject-erasure-residency`; this package freezes the shapes it consumes: tenant/session-keyed `RedactionMaps` Put/Get and `RegionProvider.Region() string`, without defining erasure API or retention deletion behavior.

## Redaction behavior and integration placements

The driver applies redaction before writes; stores do not perform redaction. The four placements and existing integration points are:

1. **Assembler:** redact user input, history/tool results, and provider context before constructing model request. `StablePrefix.Assemble(ctx, in)` and its `build(ctx, in)` in `std/assembly.go:123-172` construct the canonical request. The resolved native turn path calls the assembler from `turnConfig` in `core/drive_turn.go` (the existing call is at line 260). Enforce outside custom assembler callbacks so a custom `NativeSpec.Assemble` cannot bypass the policy.
2. **Store writes:** redact before `SessionLog.Append` in `Conversation.Send` and `conversation.appendInput` (`core/conversation.go:174-249,274-289`), before lifecycle history writes through `AppendBeforeBatch`, `AppendStepEnd`, and the lifecycle `HistoryAppender` (`core/drive_lifecycle.go:52-106`), and before steer/history appends (`core/conversation_steer.go`). Redact before `EventLog.Append` in `conversation.relay` (`core/conversation.go:359-369`), before checkpoint writes in lifecycle suspension/checkpoint creation (`core/drive_lifecycle.go`), and before notes store writes in `std/notes/notes.go`. OutputStore writes, where configured, also receive redacted blocks. Persist the unredacted originals only in the separately tenant/session-keyed `RedactionMaps` port, not in checkpoints or journal entries.
3. **Telemetry content capture:** redact before any opt-in content reaches telemetry capture. Current `std/telemetry/convention.go:54-87` filters content attributes in `Convention.ApplyAttrs`; it is not a driver redaction hook. Content capture defaults off (`ContentNone`, lines 12-27). Integrate at the capture site before `ContentFull` attributes are created; never enable raw capture as a side effect of this change.
4. **Output rehydration:** join rehydration at `Windowed.GuardStream`'s window-release boundary in `std/guard/output.go:86-166`, before the existing `release` function and before `emit`. Use the existing output-stage `Windowed` guard; do not add a second windower. Align the rehydration window with effective `Windowed.Window` (default 64, `std/guard/output.go:13-14`). Buffer an incomplete token through its closing delimiter across provider chunks. Rehydrate only complete map entries. Delete token-shaped unknown values and increment `gohan.redact.unknown_token` without token/entity/session/tenant data. The map-load join occurs before stream release on resumed and fresh runs. Public output streaming proceeds through `core/model_stream.go` into the conversation consumer; prove via `Conversation.Send` and Resume, not only guard unit tests.

Checkpoint encoding is owned by `encodeCheckpoint` (`core/checkpoint_envelope.go:46-53`); the map must remain outside its `checkpointEnvelope` shape (`core/checkpoint_envelope.go:18-25`). `decodeCheckpoint` is shared by resume and recovery (`core/checkpoint_envelope.go:55-60`), but must not rehydrate or persist the map as checkpoint content.

## Redactor contract

`std/redact` supplies deterministic, checksummed default rules and a `KeySource` with `Key(ctx context.Context, tenant string) ([]byte, error)`. HMAC-SHA-256 token input is `session || NUL || kind || NUL || canonical-value`, keyed by tenant; same entity is stable within a session and unlinkable across tenants or sessions. Store complete token-to-entity entries with tenant/session binding. A token collision for different entities is an error, never overwrite. Validate shipped rule checksums before use. Card candidates require Luhn validation; IBAN candidates require MOD-97 validation; invalid candidates remain unchanged. `FormatPreserving` and `Vaulted` modes remain unsupported until fully implemented and must fail with typed `ErrModeUnsupported` rather than claim support. Preserve the normative detector and entity vocabulary in `core/types`; do not create a duplicate vocabulary in the adapter.

## Errors and fail-closed behavior

Redaction, detector, key retrieval, and map-store errors propagate; no raw fallback is permitted. Build-time residency failures use typed `ErrResidencyMismatch` with tenant, target, required and actual region details. Unsupported token mode uses typed `ErrModeUnsupported`. Missing map/key or failed rehydration releases no pseudonym text. Unknown token-shaped output is dropped and recorded with a content-free metric. Store-write errors retain the existing error propagation path; they must not be swallowed to continue with raw content.

## Public-path test seeding

Use deterministic fixed keys and detectors, memory session/event/checkpoint stores, a `RedactionMaps` test store, and an instrumented model that captures each request. Configure a native flow using `WithNativeAgent` plus `WithRedactor(types.Redactor)`, call `Build`, then exercise `Conversation.Send`, checkpoint `Resume`, and recovery where the placement applies. Instrument each write boundary (session/event/output/checkpoint/notes and telemetry capture) and assert seeded raw entities never reach it; assert the model request receives stable pseudonyms. For streaming, split a known token across provider chunks and a release-window boundary, include a model-invented token, and assert only the mapped entity is emitted and the unknown-token metric increments once without sensitive attributes. Repeat after Resume to prove the map is fetched independently of checkpoint state. For residency, build a residency-bound tenant with each configured store reporting matching, mismatching, empty, and absent region evidence; include reachable primary and fallback profiles. Assert Build rejects invalid cases before any model call.

These are required future proofs, not evidence that runtime behavior is implemented today. Existing tests of `Windowed` alone or synthetic child results do not establish the public-path scenarios.

## Open questions and admission

No decision required by this package remains open after ADR-0157 decisions 1–3. The ADR specifies the port types, registration pattern, map persistence ownership, checkpoint exclusion, and fail-closed residency rule, and it settles the third placement: content capture is opt-in, nothing in the tree emits message content to telemetry today, so the change asserts that no telemetry path receives content and applies the redactor at the capture seam when that seam lands rather than inventing a hook. Implementation still names the concrete sink adapters it writes through against the then-live code; a configured store that cannot be identified is recorded as a missing call site, not papered over, and `Convention.ApplyAttrs` is not redaction. The `EraseSubject` ownership boundary does not change.
