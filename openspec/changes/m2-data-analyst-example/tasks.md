# Tasks: m2-data-analyst-example

A task is done when its listed scenario IDs have a passing subtest named exactly the ID on the public path and its `verify:` command is green. The offline `Sandbox` fake is deterministic and in-process: it returns scripted `ExecResult` values and scripted file bytes keyed by path, it counts `Open`, `Exec`, `Put`, `Get`, `SetEnv`, `Snapshot` and `Close`, and it guards its file map with a mutex so assertions are order-independent. The fake lives in `examples/data-analyst` and is never exported. No fixture reaches a container runtime, a network or an API key, and every filesystem write stays inside `t.TempDir()`.

Lane acceptance is the eleven scenario ids below (ten reused unchanged, one new composition id) plus the checks for the touched module. The `GATE=M2` global gate is a milestone gate, not a per-lane green gate. The adapter-owned halves of `sandbox.egress-denied` and `sandbox.exec-timeout` stay open under `m2-sandbox-adapter-conformance` and, past M2, under `m2-e2b-sandbox`; the `ClassContextOverflow` backstop stays with `m2-context-calibration-overflow`; router `Cascade`, provider failover, shared quota and multi-batch yielding are catalog-scope exclusions recorded in the design's boundary table. A scenario run that matches zero tests does not count as acceptance.
