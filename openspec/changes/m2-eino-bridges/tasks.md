# Tasks

Every task names the scenario id it binds. `verify` is the command that proves it. A `-run` pattern that matches no test exits 0, so each verify command runs with `-v` and the task is done only when the named top-level test and subtest appear in the output.

The bound existing set is three ids — two `runtime` rows and one `guards` row. `runtime.foreign-tool-under-native` is proved for the **bridge-fidelity and public-path** leg; the mixing chain leg was proven by `m2-eino-runtime`. `runtime.message-round-trip` **extends the archived eino acceptance subtest** of the same id (`openspec/changes/archive/2026-10-07-m2-eino-runtime/specs/runtime/spec.md:170`); it is not a duplicate row and adds no new id for the same claim (design.md §3 D7). `guards.origin-survives-conversion` is proved inside the `TestMessageBridge` tree in `adapter/eino` (design.md §3 D6). `runtime.governed-components-in-eino-graph` is not bound here: its acceptance row is `m2-eino-graph-native-resume`'s (`openspec/changes/m2/design.md` §2.1).

Every conformance and fidelity task names an observable assertion on the real symbol. No task proves a bridge contract by echoing the bridge back through a mock.
