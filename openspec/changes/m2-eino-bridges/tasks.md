# Tasks

Every task names the scenario id it binds. `verify` is the command that proves it; the evidence line names the file and the symbol or subtest the evidence lands in.

The bound set is three ids — two `runtime` rows and one `guards` row — and none lands alone. `runtime.foreign-tool-under-native` is proved for the **bridge-fidelity** leg only — the mixing chain was proven by `m2-eino-runtime` (`adapter/eino/foreign_tool_test.go:167`). `runtime.message-round-trip` is proved for the **eino leg only** — the adk-go leg is M3's (`design.md` §3 D4, `openspec/changes/m2/design.md` §3 conflict 3). `guards.origin-survives-conversion` is proved by the shared fidelity contract's origin round-trip (`openspec/changes/m2/design.md:107`). `runtime.governed-components-in-eino-graph` is not bound here: its acceptance row is `m2-eino-graph-native-resume`'s (`openspec/changes/m2/design.md` §2.1). Two evidence sets, both in the adapter module plus the shared suite: **(A)** the exported tool bridge, and **(B)** the message-fidelity contract.

Verify: `go -C adapter/eino test -short -timeout 2m -run 'TestForeignToolBridge|TestForeignToolUnderNative' ./...` — the middleware-order subtest passes and `TestForeignToolUnderNative` (`adapter/eino/foreign_tool_test.go:167`) still passes with the exported bridge in place of the local shim. Evidence: `adapter/eino/foreign_tool_test.go` (the shim replaced by the exported bridge), `adapter/eino/tool_bridge_test.go` (`middleware_order_preserved`).
