# Design: m2-api-freeze

## Context

The freeze is the M2 exit event: every port that exists at the end of M2 is frozen at v1, growth after the freeze goes through optional interfaces, and `m2-api-freeze` owns the port-method-set compatibility check and the `v1.0.0` tag (`docs/overview.md:108`, `:110`; `openspec/changes/m2/design.md:9`, `:149-150`). Facts verified in the worktree on 2026-10-12.

- **The gate loop.** `task api:check` iterates `for dir in . adapter/*`, reads the module path from `go.mod`, takes the newest tag of that module's version line, skips the module when there is none, and otherwise runs `go run ./tools/apicheck -dir "$dir" -tag "$tag"` (`Taskfile.yml:53-69`). `examples/` is not in the loop, and `examples/go.mod` exists (`github.com/victorzhuk/gohan/examples`).
- **Only two tags exist.** A per-module baseline probe returns: root `v0.1.0`; `adapter/otel` `adapter/otel/v0.1.0`; `adapter/anthropic`, `adapter/docker`, `adapter/eino`, `adapter/openai` and `adapter/postgres` none. `adapter/docker` is already a workspace module (`go.work`); `adapter/e2b` is not yet.
- **The tool's v1 policy ships.** `majorOf` reads the major from the tag's last path segment (`tools/apicheck/main.go:103-114`); `reportBreaks` returns an error for a v1+ module with breakages and only prints them for a pre-v1 module (`tools/apicheck/main.go:84-101`); `TestReportBreaks` covers both cases (`tools/apicheck/main_test.go:152`).
- **The tool walks past a nested module.** `loadPackages` walks the module directory it is given and skips only `testdata`, `_`-prefixed and `.`-prefixed directories — never a directory that holds its own `go.mod` (`tools/apicheck/main.go:205-244`). A root-module run therefore parses the `examples/` and `adapter/*` trees and reports their symbols under the root module; `docs/design/api-review-m0-5.md` records exactly that, under *Gate evidence*, "Surface covered", where `examples/excursions` and `examples/temporal-travel` appear in the root module's report.
- **The shapes to freeze** (`openspec/changes/m2/tasks.md:53`), read from the tree: `runtime.Runtime` = `Stepper` (`Start`, `Step`) plus `Name()` and `Granularity()` (`core/runtime/runtime.go:62-67`); `runtime.State.Backend []byte` beside the other fields (`core/runtime/runtime.go:28-39`); `runtime.StepGranularity` with `GranularityEffect` and `GranularityTurn` and no third value (`core/runtime/runtime.go:70-75`); `runtime.AgentRun` a struct carried by keyed literals (`core/runtime/runtime.go:83-97`); `types.Sandbox.Open(ctx, WorkspaceRef, SandboxPolicy) (Workspace, error)` (`core/types/sandbox.go:71-73`); `types.Workspace` with `Exec`, `Put`, `Get`, `SetEnv`, `Snapshot`, `Close` (`core/types/sandbox.go:77-84`); `types.SecretResolver.Resolve(ctx, Principal, name) (string, error)` (`core/types/secret.go:8-10`).
- **Growth is optional-interface shaped already.** `WorkspaceLister`, `SandboxResources`, `WorkspaceResource` and `SandboxHandles` sit beside the sandbox port and are reached by type assertion (`core/types/sandbox.go:86-140`), which is the rule `docs/design/compatibility.md:16-21` states.
- **The recorded gap.** `docs/design/compatibility.md:38` records that the `spec:types` port-method-set clause is unimplemented: `tools/gen_types_index.py` reads `openspec/specs/*/spec.md`, so it records declared intent and observes no shipped method set. The generated index is `docs/design/types.md`, regenerated by `task spec:types` (`Taskfile.yml:9-12`).
- **Precedent for the record.** `docs/design/api-review-m0-5.md` is where the `v0.1.0` cut was recorded with its `task api:check` output; `docs/design/compatibility.md:7` puts breaking changes under *Breaking* in `CHANGELOG.md`, which carries an `## [Unreleased]` section with a long `### Breaking` list (`CHANGELOG.md:5-7`).

## Goals / Non-Goals

**Goals:** record the frozen port shapes and the per-module `v1.0.0` tag plan in `docs/design/compatibility.md`; make `tools/apicheck` respect a nested module boundary so a run freezes exactly the module it was given; cut `v1.0.0` per module in release order; make `task api:check` diff every module against its own baseline and fail from v1 on an incompatible change; record the cut in `CHANGELOG.md` and the `docs/overview.md` M2 exit line; state the `examples/` exclusion.

**Non-Goals:** no `openspec/specs/` change (`skip_specs: true`) and no scenario id; no change to any frozen port's method set — `runtime.Runtime`, `types.Sandbox`, `types.Workspace` and `types.SecretResolver` are tagged as they ship; no new optional interface; no behaviour change; no implementation of the `spec:types` port-method-set generator clause (`docs/design/compatibility.md:38`, M4-facing); no tag for the `examples` module; no adapter code (`m2-docker-sandbox`, `m2-e2b-sandbox`, `m2-sandbox-adapter-conformance` own those legs); no `adapter/httpapi` server diff (`docs/design/compatibility.md:47` keeps that an M4 gap).

## Decisions

### D1 — The port-method-set compatibility check is `task api:check` at v1, not a new generator

`tools/apicheck` already compares every exported symbol between the tag and HEAD, method sets included: `diffTrees` walks both trees and reports a symbol that was removed or whose signature changed, and signatures are built from the full field and method lists (`tools/apicheck/main.go:170-201`, `:286-364`). What it lacks is a tag to compare against for five modules. Giving every module a `v1.0.0` baseline turns the existing gate into the check the milestone names, with no new tooling, and its v1 policy (`tools/apicheck/main.go:84-101`) makes a port that gains or loses a method fail the task from that tag on. Alternative rejected: implementing the spec-reading port-method-set generator before the freeze. It is recorded as unimplemented for a stated reason (`docs/design/compatibility.md:38`), it is M4-facing, and freezing on a new tool would gate the milestone on tooling rather than on the shipped surface. `docs/design/types.md` still records the kind of every interface, so the declared side stays documented.

### D2 — The freeze record lives in `docs/design/compatibility.md` beside the v1-candidate section

The doc is the normative compatibility process (`docs/design/compatibility.md:3`) and already carries the `v1-candidate (M0.5)` section (`docs/design/compatibility.md:40-48`). The change adds an `M2 freeze` section there with two tables: the frozen port shapes (port, declared method set, the file:line that ships it, and the stance — unchanged, conditional, sole carrier, two values, as declared) and the per-module tag plan (module dir, module path, current baseline, freeze tag, precondition). It states the `examples/` exclusion in the same section. `docs/design/types.md` is generated (`Taskfile.yml:9-12`) and is not hand-edited.

### D3 — `loadPackages` stops at a nested module boundary

At v1 the tree walk becomes a false gate: a root-module run parses `examples/**` and `adapter/**`, so an example-local exported type change would fail the root module's check against `v1.0.0` even though the root module did not change. `loadPackages` (`tools/apicheck/main.go:205-244`) therefore skips a directory that holds its own `go.mod`, so each run freezes exactly the module directory it was given — which is what the task's own description says it does ("apidiff of every module against its last tag", `Taskfile.yml:54`). The `examples/` module then leaves the root module's report, which D5 accounts for. Alternative rejected: accepting the widened surface — it makes the root `v1.0.0` tag freeze example-local shapes the root module does not own, and that contradicts `docs/design/compatibility.md:16-19`.

### D4 — Release order is root first, then each adapter after its conformance suite is green against core v1

`docs/design/compatibility.md:9` fixes the order: "Release order is core, then adapters", and `:8` fixes the precondition: an adapter reaches `v1.0.0` when its conformance suite passes against core `v1`. The root module is tagged `v1.0.0` when the M2 exit criteria pass (`docs/design/compatibility.md:7`); each adapter module (`adapter/anthropic`, `adapter/docker`, `adapter/eino`, `adapter/e2b` when it lands, `adapter/openai`, `adapter/otel`, `adapter/postgres`) is tagged `<dir>/v1.0.0` afterwards. The precondition task runs `task spec:gate GATE=M2` and requires `missing_in_scope=0`, so no tag is cut over an unmet M2 row (`openspec/changes/m2/design.md` §2). An adapter whose conformance suite is not green against core v1 keeps its pre-v1 line and its baseline gap is recorded instead of hidden.

### D5 — `examples/` stays outside the loop and is noted, not tagged

The `api:check` loop visits `.` and `adapter/*` (`Taskfile.yml:58`); `examples/` is never passed to `tools/apicheck` as its own module, so it has no version line for the gate to baseline, and it carries no tag. After D3 the example symbols also leave the root module's report. The freeze record states this plainly and points at where the examples are witnessed instead: `task examples:test` and `task examples:run` (`Taskfile.yml:124-132`). `docs/design/compatibility.md:9` already places `examples/` outside the release order — it "pins exact versions of everything" rather than publishing an API line. Adding it to the loop was rejected: it publishes a compatibility promise for code that is documentation.

### D6 — The cut is recorded in `CHANGELOG.md` and the `docs/overview.md` M2 exit line

`docs/design/compatibility.md:7` sends breaking changes while the module is `v0.x` to the changelog, and `docs/design/api-review-m0-5.md` is how the `v0.1.0` cut was recorded. `CHANGELOG.md` therefore gains the `1.0.0` release entry that closes the `## [Unreleased]` section, and `docs/overview.md:110`'s M2 row exit line is updated to the shipped result, which the milestone definition of done requires (`openspec/changes/m2/tasks.md:52`). No other process doc is touched.

## Risks / Trade-offs

- [A module is tagged `v1.0.0` before its M2 rows are met] → D4 gates every tag on `task spec:gate GATE=M2` reporting `missing_in_scope=0`; a single unmet row keeps the tag uncut and the gap recorded.
- [The `tools/apicheck` boundary change alters an existing report] → the root run stops reporting `examples/*` and `adapter/*` symbols, which is the intended fix; `TestDiffTrees` and `TestReportBreaks` must pass unchanged (`tools/apicheck/main_test.go:30`, `:152`), and the observable check is that a root run prints no `examples/` symbol.
- [A frozen port gains a method after the tag and the gate does not fail] → the v1 policy is `reportBreaks` returning an error for `majorOf(tag) != 0` (`tools/apicheck/main.go:84-101`, covered by `TestReportBreaks`); the positive control in the tasks exercises it on a scratch edit before it is trusted.
- [The `examples/` module has no compatibility witness at all after D3] → stated in the record, with `task examples:test` and `task examples:run` named as its witness (`Taskfile.yml:124-132`); it is not a published API line (`docs/design/compatibility.md:9`).
- [A tag is cut at a commit that is not the frozen tree] → the preconditions are run at the same HEAD the tag names, and the record captures the `task api:check` output for that HEAD.

## Migration Plan

Documentation and tag cutting only; no stored shape, event, wire format or goose migration is involved. Rollback is deleting the tags and reverting the doc and tool edits; the apicheck boundary change is additive to its semantics (fewer symbols per run) and reverts cleanly. The tags are cut once, in release order, and CI's api:check policy takes effect from them.

## Open Questions

None that change the specs, the approach, or the task breakdown.
