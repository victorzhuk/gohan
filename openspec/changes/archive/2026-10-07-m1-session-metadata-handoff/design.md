# Design: m1-session-metadata-handoff

## Context

The behaviour is already normative in the capability specs; this design decides the seams that connect it to the live tree. Read against the tree on 2026-10-07:

- **The title has no producer.** The `flow` *Titles* rule names `std/flow.Title` as an `Extract[string]` recipe run by the harness after the first `Done` of a session's first primary run, written with `UpdateSession` (openspec/specs/flow/spec.md:110-112). `std/flow` ships `Extract`, `Classify` and `Quarantine` and nothing else (`std/flow/extract.go:52`); no `WithTitleProfile` option exists in `core/build_options.go`.
- **The rename lock ships in the store.** `SessionMeta` carries `Title string` and `TitleLocked bool`, and `UpdateSession` sets `TitleLocked = true` on every `Title` patch (`core/stores/session.go:63-77`, `core/stores/session_memory.go:662-666`). `SessionPatch` has no other title surface. The lock is therefore already the single bit that decides whether a later title may be written.
- **The handoff control state is declared, never written.** `ControlHandoffRequested` sits between `ControlAgent` and `ControlHuman` (`core/stores/session.go:86-89`), and nothing sets it. `HandBack` flips control to `ControlAgent` and audits, with the operator-turn restore explicitly deferred (`core/session_takeover.go:105-118`). `OperatorSend` appends the operator message with `RoleAssistant` and `OriginOperator` (`core/session_takeover.go:118-139`), so the turns are already in history.
- **Control errors already travel as errors.** `CallTool` passes `SuspendError`, `AbortError` and cancellation through untouched, and `isControlError` names the class that must never render as a tool failure (`core/tool_call.go:44-47`, `core/drive_turn.go:1166-1175`). The lifecycle's terminal seam special-cases only `SuspendError`; every other error closes the run `Failed` and yields the error tuple (`core/drive_lifecycle.go:480-486`). `finishRun` and `done` already take a `types.StopReason`, and `StopHandedOff` is in the enum (`core/drive_lifecycle.go:1012-1020`, `1041-1047`, `core/types/event.go:23`).
- **The feedback machinery ships, the public path does not.** `stores.FeedbackStore` records owner-checked, idempotent entries (`core/stores/feedback.go:70`), and `stores.RecordFeedback` appends the `FeedbackRecorded` event (`core/stores/feedback_lifecycle.go:35`). No `Stack.Feedback` exists, and `gohan.feedback` appears in no registration or emission (`core/telemetry.go:23-29`, `std/telemetry/metrics.go:38-44`). The allow-list already admits `name` and `flow` and forbids `subject` (`std/telemetry/metrics.go:57-70`).
- **The fence material already ships.** `PromptSet.OperatorTurn` is rendered by both the native prompt block and `std.PromptMiddleware`, and `std/assembly` owns request shaping (`core/native_effects.go:295-315`, `std/prompts.go:11-30`, `std/assembly.go`).

## Goals / Non-Goals

**Goals:** generate the title once after the first completed turn, keep a rename authoritative, end the run on a human request as a terminal `Done`, fence the operator turns after a hand-back, and emit `gohan.feedback` with the contract's labels — turning the five owned scenarios green on the public path.

**Non-Goals:** This change adds no new event type, no new store and no second builder. It does not re-implement `stores.FeedbackStore` or the `FeedbackRecorded` path. It does not change `TakeOver`'s shipped signature, the approval-expiry path or the takeover audit vocabulary. It does not add a transport, a UI surface or a title-edit endpoint: a rename stays the existing `UpdateSession` title patch. It does not implement `Stack.ExplainHandler` or any `interop` behaviour.

## Decisions

### D1 — `std/flow` owns the recipe; core owns the trigger

`std/flow.Title(s *gohan.Stack, profile string) gohan.Flow[[]types.Block, string]` wraps `Extract[string]` with a six-word instruction and no tool, so it rides the shipped recipe, its governed model call and its validation unchanged (`std/flow/extract.go:52`; ADR-0139, ADR-0131). The trigger lives in core, because only the conversation sees the run's `Done` and holds the session index. After the conversation emits the first `Done` of a session's first primary run, it starts one `SessionChild` run through the same runs store and lifecycle the primary run used, with `CostTags.Feature = "title"` (the cost tag the rule names). The child run's `Done` is where the title is written; the primary `Done` has already been delivered, so the rule that the primary `Done` is not delayed holds by construction. The profile is `agent.WithTitleProfile(profile)` when set; the default resolves the cheapest configured profile from the stack's price table. The title run is a child of the primary session row, so it appears in the index as `SessionChild` and never competes with the primary row for a run lease.

### D2 — The rename lock is the store's `TitleLocked`, and rename always wins

`UpdateSession` already locks on any title write, and the lock is never cleared (`core/stores/session_memory.go:662-666`). Generation MUST therefore run only when `TitleLocked` is false and `Title` is empty, and its own write locks the title, so a session is titled at most once. The precedence is total: a rename writes `Title` and locks, so a later run finds a locked session and starts no title run; a generated title locks, so a later rename is the only way the title changes, and after it no further generation happens. A fork inherits the parent's title with the `(edited)` suffix and is not titled again. This is a one-bit decision, so it stays in the store rather than a second lock in core.

### D3 — A human request is a terminal control outcome, not a suspension

`request_human` is a governed built-in tool. Its execution returns a new control error, `*types.HandoffError{Context types.HandoffContext}`, which joins the class `CallTool` passes through and `isControlError` names, so it never renders as a `ToolResult` (`core/tool_call.go:44-47`, `core/drive_turn.go:1166-1175`). The lifecycle's terminal seam gains the handoff branch beside the suspension branch: it calls `finishRun(ctx, st, stores.Finished, nil, types.StopHandedOff)` and emits `done(st, nil, types.StopHandedOff)`, so the stream ends with a `Done` and never a `Suspended` (`core/drive_lifecycle.go:480-486`, `1012-1020`, `1041-1047`). No `ResumeToken` is minted, so `Resume` cannot continue the run — this is what separates the outcome from `SuspendError`. At the same seam the session control is written `ControlHandoffRequested` and the `HandoffContext` is persisted; the transition is audited `handoff_requested` under the principal, matching the takeover vocabulary. `HandoffContext` gains a durable slot on the session index: `SessionMeta.Handoff` written through `SessionPatch.Handoff`, so `TakeOver` and the operator surface read it from the same row that carries `Control`. A `HandoffError` is a terminal *control* error: distinct from `AbortError`, which closes `Failed` and yields the error tuple, and from `SuspendError`, which closes `Suspended` with a token.

### D4 — The hand-back fence is an assembly-time projection keyed on origin

`HandBack` keeps its shipped meaning — flip control to `ControlAgent` and audit — and the fence is applied where requests are shaped. `std/assembly` projects every `OriginOperator` block in history as a preceding `Text{OriginSystem, PromptSet.OperatorTurn}` block followed by the operator blocks, so the operator turns appear as one marked segment and the model's reply is `OriginModel` (model output already carries that origin). The projection keys on the block origin, not on the current control state, so it also covers the turns of an earlier hand-off and needs no flag on the session. History is never rewritten: `OperatorSend` already persists the turns once (`core/session_takeover.go:118-139`), and a rewrite would duplicate them on every hand-back and on every fork. The scenario's "two operator turns wrapped" is therefore the next `Send`'s assembled request after `HandBack`, observed through the public path.

### D5 — `gohan.feedback` carries exactly `name`, `flow`, `release`, `variant`

`Stack.Feedback` is the public recording path the `flow` *Feedback* rule names. It is owner-checked and idempotent through `stores.FeedbackStore.PutFeedback`, appends the `feedback` audit record, appends `FeedbackRecorded` through `stores.RecordFeedback`, and emits the metric (`core/stores/feedback.go:70`, `core/stores/feedback_lifecycle.go:35`). The metric is registered in `std/telemetry` as `Metric{Name: "gohan.feedback", Labels: []string{"name", "flow"}}`; the metric layer already stamps `release` and `variant` on every emission, so the observed series is exactly `gohan.feedback{name, flow, release, variant}` (`std/telemetry/metrics.go:78-84`). A numeric `Value` records a histogram; any other `Value` counts. No label carries the subject, the session, the run, the target, the comment or the correction: the allow-list admits none of them and forbids the identity names outright (`std/telemetry/metrics.go:57-70`). Cardinality is bounded by the application's declared `name` set (the tool-name grammar, `^[a-z][a-z0-9_]{0,63}$`), the registered flow names, the release and the variant — a fixed four-label product with no unbounded dimension.

## Risks / Trade-offs

- [Risk] A title run for every new session doubles the runs-store traffic on the first turn. → Accepted: it is one child run per session, it never blocks the primary stream, and a locked or already-titled session starts none.
- [Risk] A handoff error that is not recognized by an older runtime closes the run `Failed`. → Accepted and bounded by D3: the error is a control class the shipped `CallTool`/`isControlError` already pass through, and the lifecycle branch is the only new site.
- [Risk] Wrapping operator turns at assembly re-wraps turns the model already saw. → Accepted: the wrap is idempotent per request and history is immutable, so replay and fork stay stable; no turn is duplicated.
- [Risk] A new `HandoffError` type widens the control-error surface. → Accepted: it is a control error type beside `SuspendError` and `AbortError`, not a sentinel, so the closed error catalog and `spec:types` are unaffected.

## Migration Plan

No data migration is required. The change adds `std/flow/title.go`, `core/session_title.go`, `core/tool_request_human.go`, `core/feedback.go`, the `types.HandoffContext` and `types.HandoffError` types, `SessionMeta.Handoff` and `SessionPatch.Handoff`, `agent.WithTitleProfile`, and the `gohan.feedback` metric name and registration. `SessionMeta.Handoff` defaults to the zero value, so a stored session row and a request row stay compatible. The `stores` Contract `SessionMeta` and `SessionPatch` blocks (`openspec/specs/stores/spec.md:210`, `:243`) gain the handoff fields in the same implementation commit and `docs/design/types.md` is regenerated; the package ships a `stores` delta declaring the edit. The Contract edit is applied to the main spec at sync time, because a delta cannot express a Contract-block change; it grows a stored handle rather than a frozen port, which `docs/design/compatibility.md` allows. The `flow`, `telemetry`, `streams` and `stores` main specs already carry every scenario this change implements, so the deltas reproduce their requirement blocks as strict supersets and add only the normative detail they lacked; the archive merge must union the added sentences and keep every reproduced scenario. Keep the module pre-v1 and create no release tag during M1 authoring (openspec/changes/m1/design.md:20-27).
