# Tasks

Every task names the scenario ids it binds. `verify` is the command that proves it; the evidence line names the file and the symbol or subtest the evidence lands in.

The bound set is not proved in one module. `design.md` §7 declares three evidence sets and every `verify` below names the module that owns its claim: **(A)** six native scheduling rows proved in `core`, **(B)** the eino acceptance rows proved in `adapter/eino`, **(C)** `runtime.message-round-trip` proved for the eino leg only. `runtime.governed-components-in-eino-graph` is not claimed here — its acceptance row is `m2-eino-graph-native-resume`'s (`m2/design.md` §2.1), and the graph flow and `einoflow` node builders are outside this change's scope, so no task below binds it.
