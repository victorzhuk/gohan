## Structural finding: adk v2.7.1 delivers resumed input only on the llmagent path

`runner/runner.go:581` routes a root agent through the workflow engine only when `isLlmAgent(rootAgent)` holds; a custom agent built with `agent.New(agent.Config{Run: ...})` takes the plain branch at `runner/runner.go:727`. On that branch the invocation context is `internal/context.NewInvocationContext`, whose `ResumedInput` always returns `(nil, false)` (`internal/context/invocation_context.go:162`). The resume-input map exists only on the workflow path (`agent/common_context.go:396-398,459-466`, populated at `workflow/scheduler.go:381-390`).

Consequence: `workflow.NewRequestInputEvent` still records the native long-running call id in the session, but no resumed answer can reach a custom agent body. The adapter therefore declares `native-pause-resume` as a `Replay` capability and resumes parked calls through `replayCall`, which the eino backend's turn boundaries already match. Making the native path available would require rebuilding the runtime on `llmagent`, whose ReAct loop runs several model calls per invocation and would break one-turn-per-Step and `MaxTurns` accounting.
